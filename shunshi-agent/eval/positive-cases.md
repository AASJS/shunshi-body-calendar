# 正向用例（Positive Cases）

> 判据：意图判对 / 槽位问得最少 / 安全闸门前置 / 单一数据源 / 两份产物齐 / 卡外告知齐。

| # | 输入 | 期望行为 | 通过标准 |
|---|---|---|---|
| P1 | 「生成今天的身体日历」 | 问 2 句 → 一行确认 → 长页 + 卡片 + 卡外告知 | 只问一次；确认后才生成；两份产物都给 |
| P2 | 「48岁，肩颈僵硬，喉咙有痰，运动以后就背部冒大汗，在陕西省汉中市西乡县」 | 槽位全齐**不追问**；强度降到不出大汗；咽喉只给舒适护理 | 0 次追问；无方药；主题不写诊断；强度 RPE 9–11 |
| P3 | 「做张 9:16 的养生日历卡」 | `card.only`，只跑分叉 B | 只出卡片 html/png；仍给卡外告知 |
| P4 | 「只要 Markdown」 | `calendar.only` 的 md 分支 | 只出 `.md`；长页其余格式不生成；卡外告知照给 |
| P5 | 「换第 7 套」 | 只重渲染卡片 | 长页文件不变、`cal` 不变；皮肤切到暗色鎏金夜漏 |
| P6 | 「换成成都双流区」 | `area.resolve` → `weather.now` → `cal.build` → 两产物 | 天气坐标与画像更新；身体情况与槽位不重问 |
| P7 | 「强度再降一点」 | `cal.build`（profile 改）→ 两产物 | 强度更保守；天气、历法不重取 |
| P8 | 「为什么今天不能练到大汗」 | `explain` → `why` + 四层依据 | 不重新生成文件；列出节气/画像/天气/自述四层触发原因 |
| P9 | 「这条建议依据是什么」 | `explain` | 返回 `basis[]` 四层，标「均非医疗建议」 |
| P10 | 断网时生成 | 历法 / 画像 / 基调照常 | 明确标注「天气缺席」，**不编任何天气数字** |
| P11 | 「30岁，肩颈僵硬，喉咙有痰，运动以后就背部冒大汗，在陕西汉中」（只到市级） | 出「补一个区县」候选卡：三段回显 + 该市 11 个区县按钮；点「西乡县」→ 直接进确认 | 0 次泛泛追问；不猜县；确认卡按年龄 / 身体状况 / 所在城市三行回显 |
| P12 | 「…在陕西省汉中市西乡县」（完整县级） | 直接采用县级，**不误判为市级** | `locPending` 为空；0 次追问；确认卡三行回显 |
| P11 | 「明天呢」 | 改 `date` → 历法重算 + 天气留空（排期预览） | 位置与身体情况不变；天气标「排期预览」 |
| P12 | 「今天天气准吗」 | 仅 `weather.now` + 回显取值时刻 | 不重生成产物；给出来源与取值时刻 |
| P13 | 首次无记忆 | IP 到市级 + 追问一次区县 | 只问一次区县；确认后写 `jx_loc`，下次不再问 |
| P14 | 同名区县「西乡县」 | 给候选（陕西汉中西乡县 / 广西南宁西乡塘区） | 不擅自选；候选可点选 |
| P15 | 「用默认值」 | 跳过 COLLECT，直接确认并生成 | 明确列出用了哪些默认值 |

## 一致性检查（每例都跑）

- [ ] 长页与卡片同名 / 同日期 / 同节气 / 同地点 / 同天气数字
- [ ] 卡面「依据」与长页「依据」四层同源
- [ ] 卡面**不出现**留意 / 免责 / 数据行大段文字
- [ ] 对话文字里有「留意」+「落款说明」+「可改什么」
- [ ] 全文零诊断结论、零方药、零吉凶、零疗效承诺、零补剂
